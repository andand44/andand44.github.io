# DuckDB

## Определение
DuckDB — это высокопроизводительная встраиваемая (in-process) реляционная система управления базами данных (СУБД), предназначенная для аналитической обработки данных (OLAP). В отличие от традиционных СУБД, таких как PostgreSQL или MySQL, DuckDB не требует запуска отдельного серверного процесса и работает внутри основного приложения. Благодаря своей архитектуре и поддержке стандарта SQL, её часто называют «SQLite для аналитики».

## Зачем нужно
DuckDB создана для упрощения и ускорения локальной аналитики данных. Основные причины её использования:
1. **Отсутствие инфраструктуры:** Не нужно настраивать серверы, кластеры или управлять конфигурациями. База данных — это просто файл или процесс в памяти.
2. **Высокая производительность (OLAP):** Использует векторизованное выполнение запросов, что делает её невероятно быстрой для агрегации, фильтрации и объединения больших наборов данных.
3. **Бесшовная интеграция с Data Science:** Идеально работает с Python (Pandas), R и Apache Arrow. Позволяет выполнять SQL-запросы напрямую к файлам CSV, Parquet или JSON, не загружая их полностью в память.
4. **Работа с данными больше оперативной памяти:** Может обрабатывать наборы данных, превышающие объем доступной RAM, за счет эффективного сброса данных на диск (out-of-core processing).

## Пример
Пример использования DuckDB в Python для выполнения аналитического SQL-запроса напрямую к файлу формата Parquet с получением результата в виде Pandas DataFrame:

```python
import duckdb

# Создаем подключение к базе данных в оперативной памяти
con = duckdb.connect(database=':memory:')

# Выполняем SQL-запрос напрямую к файлу Parquet
# DuckDB автоматически определит схему и прочитает данные
query = """
    SELECT 
        department, 
        COUNT(*) as employee_count, 
        AVG(salary) as avg_salary
    FROM 'employees.parquet'
    GROUP BY department
    ORDER BY avg_salary DESC
"""

# Выполняем запрос и сразу получаем результат в виде DataFrame
result_df = con.execute(query).fetchdf()

print(result_df)
```
